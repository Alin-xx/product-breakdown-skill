# Harness 案例说明

本案例来自同一项目中的三份成品报告，用于理解报告形态、视觉语义和跨报告链接。它们是示范，不是强制文案或固定结论；分析其他产品时必须重新取证。

## 案例文件

- [DeepSeek Harness 产品架构拆解](../assets/examples/deepseek-harness-product-architecture-report.html)：单产品完整架构报告。
- [OpenAI Codex Harness 产品架构拆解](../assets/examples/codex-harness-product-architecture-report.html)：单产品完整架构报告。
- [DeepSeek Harness vs Codex Harness 对比总览](../assets/examples/deepseek-harness-vs-codex-harness-comparison.html)：引用两份深拆报告的轻量对比入口。

## 可复用做法

### 1. 同一 Schema，不同产品识别

两份单产品报告沿用相同章节 ID、证据等级、表格字段和 Mermaid 类型，便于横向复核；DeepSeek 使用紫色主识别，Codex 使用绿色主识别。可变的是产品气质，稳定的是证据语义。

### 2. 深拆与总览分层

单产品报告承载完整证据、五流、九层、实体、时序、全景、风险和未知；对比总览只保留决策所需维度，并链接回两份深拆。这样既避免一个超长页面，也保证比较结论可追溯。

### 3. 对比使用共同问题

对比表按核心抽象、扩展模型、状态、会话、工具、协议、安全和适用场景等共同问题逐行比较，而不是把两个产品介绍并排粘贴。

### 4. 源码快照作为时间边界

报告标题区记录仓库提交哈希和日期。涉及快速演进产品时，结论必须绑定快照；未来更新应新建或明确更新版本，不悄悄覆盖时间语义。

### 5. 美化服务于扫描

单产品报告使用一个主色，比较报告使用两个等权对象色；证据、风险和建议另用固定语义色。表格可横向滚动、移动端栅格折叠、暗色随系统设置。视觉选择帮助读者识别对象与结论，不为装饰而增加组件。

## 需要改进后再复用的点

这些案例形成于本 Skill 视觉规范完善之前。复用结构时应升级：

- 增加打印样式、清晰焦点态与 reduced-motion 处理；
- 正文提升到 16px，并减少纵向表格网格线；
- 将章节导航做成更明确的当前位置反馈；
- 在线交付时把本地源码链接改为固定 commit 的远程链接，避免部署后失效；
- 对比总览补充稳定 section ID、证据等级图例和“不可比项”。

因此，案例回答“这个项目怎样组织三份报告”，[html-visual-system.md](html-visual-system.md) 和模板回答“下一份报告应达到什么质量”。

## 使用方式

仅在以下情况读取本案例：用户要求参考 Harness 项目的报告风格、要生成单产品深拆加对比总览的报告组、或需要理解该 Skill 的完整示例。普通单报告任务无需加载三个大 HTML 文件；先读本说明，再按需要打开一个对应案例。
