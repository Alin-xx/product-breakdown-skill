1. 执行摘要

结论：开源 Codex Harness 是以 Rust codex-core 为业务内核、以 Thread/Turn/Item 与事件流为交互协议、以动态 ToolRouter 连接内建/MCP/插件/托管工具、以权限配置+审批+OS 沙箱约束副作用的本地 Agent 平台。TUI、exec、app-server 和外部客户端是不同投影面。
控制核心
已确认run_turn 循环：模型返回工具调用则执行并把结果送回下一次采样；仅返回消息且无后续输入则结束。
协议核心
已确认app-server 通过 JSON-RPC 暴露 Thread/Turn/Item、流式通知、审批与配置。
安全核心
已确认权限 profile、AskForApproval、Guardian reviewer、exec policy、网络策略与平台沙箱分层协作。

合理推断Codex 的产品重心是“稳定的执行控制面 + 丰富的宿主集成”，而不是让所有能力都成为同构插件；这带来更强协议/治理深度，也提高 core 与兼容表面的工程复杂度。

16. 风险

优先级风险触发影响当前控制
P0权限/沙箱组合降级平台不支持精确 deny-read 或错误使用 full access越权读取/写入/联网无法等价时 fail closed；内建 profiles 与 managed requirements
