一句话差异

DeepSeek Harness

“组合优先”：Cordis 只提供插件生命周期和事件机制，模型、会话、工具、Agent loop、沙箱、UI 都可由插件替换；事件日志是恢复与回放的唯一真源。

Codex

“控制面优先”：Rust core 固化 Thread/Turn/Item、执行循环、安全和协议主干，再通过动态 ToolRouter、MCP、Plugins、Apps 与 app-server 向外扩展。

选型结论

如果目标是搭建可自定义 Agent 平台：优先研究 DeepSeek 的插件树、capability seam、事件日志和 profile 分发。
如果目标是搭建生产级编码 Agent 控制面：优先研究 Codex 的 Thread/Turn/Item、app-server、ToolRouter、上下文增量、审批与跨平台沙箱。
理想融合：以 DeepSeek 的可替换能力接口为上层扩展模型，以 Codex 的权限证明、协议版本化和 per-step 工具计划作为执行治理内核。

最值得借鉴的设计

来自 DeepSeek来自 Codex
模型可见即日志化；插件 effect 可逆；source plane 与 artifact plane 分离；profile/bundle/patch 可复现装配；完整 capability seam 需 Definition/Provider/Consumer 三角色。每 step 捕获一致上下文/工具视图；工具暴露模式与碰撞检测；稳定/实验 API capability gate；JSONL canonical history 与 SQLite metadata 分离；权限→审批→沙箱→网络的多层强制。

共同风险

  • 多 Agent 会放大并发、成本、文件冲突与取消传播问题。
  • 动态工具集合会增加可解释性、兼容性与缓存稳定难度。
  • “完成”不应只看最终消息，需交叉检查工具结果、资产、状态写入与子任务终态。
  • 本地沙箱能力存在平台差异；必须把文件、网络、进程三轴分别声明。
  • 开源仓库不能证明闭源模型路由、计费、租户隔离与线上 SLA。
